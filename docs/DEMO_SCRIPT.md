# まなび環境ラボ 動画撮影用 操作手順書

NIJIN教育万博2026 応募動画で、アプリの操作部分を撮影するための手順書です。
**画面に表示される投稿・対応・結果は、すべて架空のデモデータです。**

---

## A. 撮影前の準備

### 1. アプリの起動

プロジェクトのフォルダで、次のコマンドを実行します。

```bash
npm install      # 初回のみ
npm run dev
```

表示された URL（通常は `http://localhost:5173`）をブラウザで開きます。

本番と同じ状態で撮影する場合は、次のコマンドを使います。

```bash
npm run build
npm run preview  # 通常は http://localhost:4173
```

### 2. デモデータのリセット

撮影のたびに、必ずデモデータを初期状態に戻してください。

1. どの画面でもよいので、ページの一番下（フッター）までスクロールする
2. 右下（スマートフォンでは左下）の **「デモデータをリセット」** を押す
3. 確認ダイアログで **「初期状態に戻す」** を押す
4. 「デモデータを初期状態に戻しました。」と表示されれば完了

リセットすると、新しく投稿した困りごとや先生の対応の記録は消え、最初の架空データ5件に戻ります。

### 3. ブラウザの推奨表示幅

| 撮影する画面 | 推奨サイズ |
| --- | --- |
| パソコン画面として撮影 | 幅 1440px × 高さ 900px 程度（ブラウザの表示倍率は 100%） |
| スマートフォン画面として撮影 | 幅 375px（開発者ツールの端末表示で iPhone SE などを選ぶ） |

- 幅 1280px 以上では、ヘッダーにすべてのメニューが表示されます。
- それより狭い幅では、右上の「≡」ボタンからメニューを開きます。

### 4. 画面録画の前に確認すること

- [ ] デモデータをリセットした（上記の手順2）
- [ ] 画面上部に、保存データに関するお知らせ（黄色または赤の帯）が出ていない。出ている場合は「×」で閉じる
- [ ] ブラウザの拡張機能のアイコン、ブックマークバー、通知などが映り込まない
- [ ] ブラウザのプライベートモードを使っていない（データを保存できない場合があるため）
- [ ] OS の「視差効果を減らす／アニメーションを減らす」設定を確認した（オンの場合、控えめなフェード表示が無効になります。動作に影響はありません）
- [ ] 入力する文章（下記）を手元に用意した

## B. 操作シナリオ

所要時間の目安は、操作だけで約2分です。編集で20〜30秒程度にまとめることを想定しています。

### 生徒の操作

| # | 操作 | 画面に表示されること |
| --- | --- | --- |
| 1 | ホーム画面（`/`）を開く | 「教室の『困った』を、『変わった』に。」 |
| 2 | **「生徒として使う」** を押す | 「困りごとを伝える」画面 |
| 3 | 「1. 何に困っていますか？」で **「音」** を選ぶ | 「音」のカードに青い枠とチェック |
| 4 | 「2. どんな場面で困りますか？」で **「授業の始まり」** を選ぶ | 同上 |
| 5 | 「3. どんな困りごとですか？」で **「椅子を動かす音」** を選ぶ | 同上 |
| 6 | **「内容を確認する」** を押し、内容を確認して **「この内容で投稿する」** を押す | 確認画面で「授業の始まりに、椅子を動かす音が気になる」→ 完了画面で「困りごとを受け付けました」「対応状況は［未確認］です」 |

### 先生の操作

| # | 操作 | 画面に表示されること |
| --- | --- | --- |
| 7 | ヘッダーの **「ダッシュボード」** を押す（スマートフォンでは「≡」→「ダッシュボード」） | 概要カードの「未確認」が 2件。一覧の先頭に今投稿した困りごと |
| 8 | 先頭の投稿の **「対応を考える」** を押す | 「改善プランの検討」画面 |
| 9 | 「1. 改善案の参考例を確認する」で、**「椅子の移動方法を工夫する（持ち上げて静かに動かすよう声をかける）」** の **「この案を対応方針に使う」** を押す | ボタンが「対応方針に選択中」に変わり、「学校としての対応方針」に文章が入る（対応状況はまだ変わらない） |
| 10 | 「2. 対応状況を選ぶ」で **「試行予定」** を選ぶ。「その対応を選んだ理由」に入力例Aを入力し、**「変更を保存」** を押す | 画面下の保存バーに「保存しました。…」 |
| 11 | 続けて **「改善済み」** を選ぶ。「試した結果」に入力例Bを入力し、**「変更を保存」** を押す | 同上。右側のプレビューに「改善済み」と結果が表示される |

**入力例（すべて架空の内容です）**

- 入力例A（その対応を選んだ理由）：`（架空）道具を使わずに、すぐに全員で始められるため。`
- 入力例B（試した結果）：`（架空の結果）2週間試したところ、授業の始まりが静かになったという声がありました。`

> 「改善済み」で保存するには「試した結果」の入力が必要です。未入力のまま保存すると、エラーが表示されて保存されません。

### 結果の確認

| # | 操作 | 画面に表示されること |
| --- | --- | --- |
| 12 | 保存バーの **「改善レポートを見る」** を押す（またはヘッダーの「改善レポート」） | 「改善のまとめ」に「困っていたこと → 学校が考えた対応 → 結果」が並ぶ。「改善までの流れ」に「1件目 投稿」「2件目 試行予定に変更」「3件目 改善済みに変更（結果を共有）」が表示される |

（任意）生徒側の表示も見せる場合は、ヘッダーの **「対応状況を見る」** を開きます。先頭のカードに「改善済み」と学校の対応が表示されます。

> 「試行中」は保存していないため、レポートには表示されません。これは正しい動作です（実際に記録された出来事だけを表示します）。

## C. 動画で映すべき画面

| 画面 | 見せたいポイント |
| --- | --- |
| ホーム（`/`） | ファーストビュー全体。「教室の『困った』を、『変わった』に。」と、右側の「伝える → 試す → 確かめる」のイメージ |
| 投稿確認（`/student/new` の確認画面） | 「授業の始まりに、椅子を動かす音が気になる」。選ぶだけで伝えられること |
| 先生の対応編集（`/teacher/issues/…`） | 参考例から対応方針を選ぶ場面と、対応状況の選択、保存バーの「保存しました」 |
| 改善レポート（`/report?issueId=…`） | 「改善のまとめ」の3つのカードと、「改善までの流れ」のタイムライン |

## D. 注意事項

- 動画内で、**すべて架空のデモ操作である**ことを明示してください（例：画面上の「デモ版」表示を映す、テロップで補足する）。
- 実際の学校で改善が実証されたように説明しないでください。レポートの「改善済み」は、デモ上の記録の状態です。
- 実際の生徒の名前、学校名、健康に関する情報など、**個人情報を入力しないでください**。入力するのは上記の架空の文章だけにしてください。
- 動画内の操作順と、画面に表示される内容（対応状況・日時・履歴）が一致するようにしてください。撮り直す場合は、必ずデモデータをリセットしてから最初から操作してください。
- タイムラインの日時は、実際に操作した日時がそのまま表示されます。続けて操作すると同じ分の記録が並び、その場合は秒まで表示されます。日時を編集で加工しないでください。
